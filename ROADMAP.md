## ✅ Sprint 2 — Media Layer (завершён 2026-07-01)

**Цель:** Полностью рабочий слой взаимодействия с медиаплеерами Android — фундамент для будущего Voice Layer. Без Vosk, без wake word, без LLM.

> Изначально запланированные «Ручной пульт управления» (Sprint 2) и
> `NotificationListenerService` + метаданные (Sprint 7) объединены и
> реализованы здесь одним слоем, по решению из брифа Sprint 2.

- [x] `MediaControllerRepository` — единая точка взаимодействия с
      `android.media.session.MediaController` (framework API, без новых
      зависимостей)
- [x] `MediaMetadataMapper` — преобразование `MediaMetadata` / `PlaybackState`
      в `MediaPlaybackState`
- [x] `DjNotificationListenerService` — обнаружение активных MediaSession
      через `MediaSessionManager.getActiveSessions()`
- [x] `SessionMediaRemote` — единственная реализация `MediaRemote` +
      `MediaStateProvider`; Play/Pause/Next/Previous через
      `MediaController.transportControls`, с fallback на
      `KeyEventMediaRemote`, если активная сессия ещё не обнаружена
- [x] Получение метаданных: название, исполнитель, альбом, наличие обложки,
      состояние воспроизведения, позиция, длительность, приложение-плеер
- [x] Настройки: статус и переход к предоставлению доступа к медиасессиям
- [x] Debug Screen: секция "Воспроизведение" с полным набором полей и честным
      статусом, если сессия недоступна

**Результат:** Media Layer — единственная точка взаимодействия с
музыкальными приложениями, готова к подключению Voice Layer в Sprint 3.

**Ограничение:** доступ к медиасессиям — особое разрешение уровня ОС
(`Settings.ACTION_NOTIFICATION_LISTENER_SETTINGS`), включается только
пользователем вручную; автоматический запрос системой не предусмотрен.

## ✅ Sprint 3 — Offline Voice Control MVP (завершён 2026-07-01)

**Цель:** Полностью локальное голосовое управление: микрофон → Vosk → Intent
Parser → Media Layer → команда плееру. Без интернета, без wake word, без
управления громкостью голосом (объём этого спринта поглощает старые планы
Sprint 3 «Аудиопайплайн» и Sprint 4 «Vosk ASR» + голосовую часть Sprint 5).

- [x] `commands.json` (assets) — конфигурация фраз вместо хардкода в командах
- [x] `VoiceCommandConfigLoader` — загрузка и кэширование конфигурации
- [x] `AndroidAudioRecorder`: реальный `AudioRecord` → 16kHz mono PCM16
      `Flow<ByteArray>`, RMS-уровень сигнала для DebugScreen, корректное
      освобождение микрофона
- [x] Интеграция Vosk SDK (`com.alphacephei:vosk-android`) + JNA
- [x] `VoskModelProvisioner` — разворачивает офлайн-модель из assets в
      локальное хранилище (чистый файловый I/O, без сети)
- [x] `VoskSpeechRecognizer`: потоковое распознавание в Grammar Mode,
      confidence на основе `result[].conf`
- [x] `GrammarBuilder`: грамматика строится из `commands.json`, без прошлой
      привязки к `CommandRegistry`
- [x] `KeywordIntentRecognizer` переписан на словарь из `commands.json`
      (регистронезависимое сравнение/`contains`, без LLM)
- [x] `VoiceEngine` (`:service/voice`) — оркестрация всего пайплайна на
      `Dispatchers.IO`, не блокирует главный поток
- [x] `DjVoiceService` — отдельный Android Service, запускается/останавливается
      вместе с `DjForegroundService`, переживает его перезапуск
- [x] Debug Screen: раздел «Voice» (статус, модель, фраза, confidence,
      Intent, Action, время обработки) + журнал последних 10 команд
- [x] Неизвестная команда → `Intent: UNKNOWN`, `Action: None`, никаких действий
- [x] `DjCommand.triggers` и `CommandRegistry.findByTrigger` удалены —
      единственный источник фраз теперь `commands.json`

**Результат:** голосовой цикл "Пауза"/"Продолжай"/"Следующий"/"Предыдущий"/
"Что играет" работает локально через Media Layer.

**Обновление (Sprint 3.1):** офлайн-модель Vosk (`vosk-model-small-ru`, ~45 МБ)
теперь добавлена в репозиторий (`feature/src/main/assets/model/`) — блокер
из первой версии этого раздела снят. `VoskModelProvisioner` по-прежнему
корректно возвращает `null` и ничего не роняет, если модель вдруг
отсутствует — это ограничение среды сборки этого агента (нет Android SDK),
а не приложения.

## ✅ Sprint 3.1 — Voice UX & Recognition Improvements (завершён 2026-07-01)

**Цель:** довести голосовое управление до состояния, пригодного для
ежедневного использования — без TTS, LLM и облачных сервисов.

- [x] `commands.json` расширен: словоформы, разговорные варианты для
      PAUSE/PLAY/NEXT/PREVIOUS/QUERY_NOW_PLAYING
- [x] `TextNormalizer` (`feature/voice`) — lowercase, ё→е, без пунктуации,
      схлопывание пробелов; используется и Intent Parser, и Debug Screen
- [x] Confidence threshold: по умолчанию 80%, диапазон 50–95%, настройка
      через Slider в Settings; распознавания ниже порога не выполняются,
      причина отказа показывается в Debug Screen
- [x] Debug Screen: Raw Text, Normalized Text, Confidence, Intent, Action,
      Execution Result, Reject Reason — плюс журнал с этими же полями
- [x] Два режима: `VoiceListeningMode.CONTINUOUS` (как в Sprint 3) и
      `WAKE_WORD` — лёгкое ожидание активационной фразы вместо постоянного
      полного распознавания команд
- [x] `WakeWordDetector` — абстракция для активации; `VoskWakeWordDetector`
      использует тот же Vosk с маленькой грамматикой ("диджей"/"dj"/"джей"),
      что не привязывает Voice Layer к конкретному будущему движку
      (Porcupine/OpenWakeWord подключаются заменой одной реализации)
- [x] Диалоговое окно после активации: 3–15 сек (по умолчанию 6),
      настраивается в Settings, сбрасывается при каждой распознанной фразе
- [x] Голосовые команды переключения режима: "Пока слушай" → Continuous,
      "Перестань слушать" → Wake Mode — перехватываются в `VoiceEngine`,
      никогда не доходят до `CommandDispatcher`/Media Layer
- [x] Управление громкостью: громче/тише/максимум/минимум/"громкость N
      процентов" (параметризованная команда через regex + `CommandContext.intent`)
- [x] Bluetooth-микрофон: настройка Auto/Phone/Bluetooth; текущий источник
      виден в Debug Screen
- [x] Мелкая полировка анимаций: `animateContentSize()` на карточках
      MainScreen и секциях Debug Screen — без полного редизайна

**Результат:** Voice Layer готов к ежедневному использованию: меньше
ложных срабатываний (confidence threshold), больше принимаемых формулировок
(расширенный словарь), два режима прослушивания, управление громкостью,
полная диагностика на Debug Screen.

**Ограничения:**
- Полноценный wake-word движок (Porcupine/OpenWakeWord) не подключён —
  используется тот же Vosk с урезанной грамматикой; архитектура
  (`WakeWordDetector`) готова к замене без переписывания `VoiceEngine`.
- Самопроверка выполнена по коду и API-контрактам (аудио/Vosk/DataStore);
  реальный прогон на устройстве (Bluetooth-гарнитура, оба режима
  прослушивания, пороги confidence) — за пользователем, т.к. в среде сборки
  этого агента нет Android SDK и физического микрофона/Bluetooth.

## ✅ Sprint 3.1.1 — Bluetooth SCO lifecycle redesign (завершён 2026-07-01)

**Проблема:** первая версия Bluetooth-микрофона (см. выше) держала SCO
активным на всё время, пока движок вообще слушал (включая ожидание wake
word) — headset оставался в режиме "звонка" гораздо дольше необходимого.

**Цель:** SCO активен только непосредственно во время записи голосовой
команды, никогда — в состоянии ожидания.

- [x] Настройка «Источник микрофона»: Auto / Phone / Bluetooth
      (`MicrophoneSource`, персистится в `DjSettings`)
- [x] Auto и Phone никогда не обращаются к Bluetooth SCO API вообще — только
      явный выбор Bluetooth активирует его
- [x] `AudioRecorder.start(allowBluetooth: Boolean)` — Bluetooth теперь
      решение конкретной сессии записи, а не глобальное состояние рекордера
- [x] Ожидание wake word в Wake Mode всегда использует телефонный микрофон
      (idle-состояние по определению не может держать Bluetooth в call mode)
- [x] Диалоговое окно (Wake Mode) и вся сессия Continuous-режима — каждая
      открывает свою собственную запись/SCO-сессию, закрывающуюся сразу по
      завершении (`audioRecorder.stop()` сразу после окна/распознавания)
- [x] SCO-хендшейк ожидается по широковещательному
      `ACTION_SCO_AUDIO_STATE_UPDATED` (с таймаутом 2 сек) перед началом
      записи — не начинаем захват через путь, который ещё не подключился
- [x] `stopBluetoothSco()` вызывается сразу в `finally`-блоке записи —
      A2DP-воспроизведение восстанавливается как можно быстрее

**Результат:** Bluetooth-гарнитура никогда не остаётся в режиме звонка,
пока голосовой сервис простаивает; SCO включается только непосредственно
перед записью команды и выключается сразу после её завершения.

## ⚠️ Sprint 3.2 — Voice UX Polish (код завершён 2026-07-01, но НЕ считался стабильным на устройстве — см. Sprint 3.3)

**Цель:** сделать голосовое управление естественным, понятным и
предсказуемым — без изменений в TTS/LLM/поиске музыки, только UX и
архитектура Voice Layer.

- [x] Найден и исправлен корневой баг Wake Mode: `VoskWakeWordDetector`
      завершал ожидание wake word по ЛЮБОМУ финальному результату Vosk, а в
      Grammar Mode любой не подходящий под словарь звук/шум возвращается как
      непустая строка `"[unk]"` — из-за этого сессия ожидания постоянно
      перезапускалась, что и создавало ощущение "как Continuous Mode".
      Теперь ожидание завершается только на реальном совпадении с
      wake-фразой; `AudioRecord`/`Recognizer` спокойно висит открытым, пока
      фраза не произнесена
- [x] `VoiceOverlayController` — компактный несблокирующий оверлей
      (`WindowManager`, `TYPE_APPLICATION_OVERLAY`, `FLAG_NOT_TOUCHABLE |
      FLAG_NOT_FOCUSABLE`) с плавным fade/scale-появлением, пульсирующим
      индикатором и обратным отсчётом ("🎧 DJ — Слушаю... Ns"); появляется
      сразу после wake word, исчезает по завершении диалогового окна
- [x] Настройка «Draw over other apps» (`SYSTEM_ALERT_WINDOW`) +
      `OverlayAccess` helper + карточка в Settings, аналогичная разрешению
      на доступ к медиасессиям
- [x] `FeedbackManager.onActivation()` подключён к моменту обнаружения wake
      word — короткий сигнал активации теперь реально звучит (success/error
      сигналы уже были подключены через `CommandDispatcher`)
- [x] Новая настройка «Звуковые сигналы» (`soundFeedbackEnabled`,
      DataStore) — `BeepFeedbackManager` проверяет её перед каждым сигналом
- [x] Таймер диалогового окна продлевается ТОЛЬКО после успешно
      выполненной команды — шум, `[unk]`, отклонённые по confidence и
      неудавшиеся команды больше не продлевают окно бесконечно
- [x] Wake Word UX подтверждён по коду: обнаружение "Диджей" только
      открывает диалоговое окно и никогда не доходит до `CommandDispatcher`
- [x] `VoiceEngineState` расширен: `Idle, Initializing, WaitingWakeWord,
      Listening, Processing, Executing, Sleep, Error` — отражает полный
      жизненный цикл, видно на Debug Screen вместе с обратным отсчётом окна
- [x] Освобождение ресурсов подтверждено: `VoiceEngine.stop()` и конец
      диалогового окна гарантированно вызывают `audioRecorder.stop()`,
      `speechRecognizer.release()` и `voiceOverlayController.hide()` —
      Bluetooth SCO закрывается тем же путём, что и в Sprint 3.1.1

**Известные ограничения / не проверено в песочнице:** нет Android SDK, нет
физического устройства и Bluetooth-гарнитуры в этой среде — сборка проекта,
визуальный вид оверлея, реальная пульсация и возврат A2DP должны быть
проверены пользователем на устройстве. Apple-style полировка ограничена тем,
что можно сделать через нативные Android View API без Compose в `:service`
(scale/alpha анимации через `View.animate()`/`ValueAnimator`,
`OvershootInterpolator`); RenderEffect-блюр (API 31+) и
`androidx.dynamicanimation` пружинные анимации сознательно не добавлялись —
не требовались для соответствия десяти пунктам задания, полноценный
редизайн не входил в scope Sprint 3.2.

**Результат:** Wake Mode ведёт себя так, как задумано (тихое ожидание →
беззвучное определение → короткий сигнал → диалоговое окно с таймером и
оверлеем → полное освобождение ресурсов → возврат к ожиданию), с видимой и
слышимой обратной связью на каждом шаге.

## 🔧 Sprint 3.3 — Stabilization (код завершён 2026-07-01, ждёт проверки на устройстве)

**Причина:** пользователь протестировал Sprint 3.2 на реальном устройстве и
явно заявил, что спринт не считается завершённым — новые функции не
добавлялись, весь спринт посвящён стабилизации уже реализованного.

- [x] **Settings не прокручивался.** `SettingsScreen`'s `Column` не имел
      `verticalScroll` (в отличие от `DebugScreen`, где он есть) — при
      достаточном числе разрешений/настроек нижние элементы были недоступны.
      Добавлен `.verticalScroll(rememberScrollState())`.
- [x] **Найдена и устранена первопричина падения приложения при
      произнесении "Диджей" (не обходной путь).** `VoiceOverlayController`
      мутировал `View` и вызывал `WindowManager.addView()`/`removeView()`
      прямо из корутины `VoiceEngine`, которая работает на
      `Dispatchers.IO` — потоке без `Looper`. `WindowManager.addView()`
      требует `Looper` на вызывающем потоке; первый же вызов (ровно в
      момент показа оверлея после wake word) кидал необработанное
      исключение, которое ничем не перехватывалось — оно валило процесс
      целиком. Исправлено переносом ВСЕЙ работы с `View`/`WindowManager`
      на главный поток через `Handler(Looper.getMainLooper())`; ни одно
      публичное намерение контроллера больше не выполняется инлайн.
- [x] **Обработка исключений с указанием этапа.** `VoiceEngine` теперь
      отслеживает `currentStage` (`waiting_wake_word`,
      `wake_word_detection`, `overlay_show`, `dialog_window`,
      `recognition_processing`, `command_dispatch` и т.д.) и оборачивает
      каждую сессию в `try/catch`: любое исключение логируется с меткой
      этапа через `DjLogger.voiceError()` (виден в «Последняя ошибка» на
      Debug Screen) и переводит `VoiceEngineState` в `Error("[этап] ...")`
      вместо падения всего приложения. Добавлен и `CoroutineExceptionHandler`
      на `engineScope` как последний рубеж защиты. Ресурсы (`AudioRecorder`,
      оверлей) гарантированно освобождаются в `catch`-блоке независимо от
      того, на каком этапе произошёл сбой.
- [x] **Найдено и исправлено зависшее состояние.** `handleRecognition()`
      переводил `VoiceEngineState` в `Processing`/`Executing`, но при
      отклонении по confidence или при переключении режима не возвращал
      его обратно в `Listening` — Debug Screen застревал на
      «Распознаёт...» до конца диалогового окна. Исправлено единым
      `finally`-блоком, который гарантированно возвращает состояние в
      `Listening` при выходе из функции любым путём (успех, отклонение,
      переключение режима или исключение).
- [x] Пройдена ревизия переходов состояний Voice Layer
      (`WaitingWakeWord → Listening → Processing/Executing → Sleep →
      WaitingWakeWord`, полная остановка → `Idle`) — зависаний, кроме
      описанного выше и уже исправленного, не найдено.
- [x] Пройдена ревизия жизненного цикла `DjForegroundService`/
      `DjVoiceService`/`AndroidAudioRecorder` — уже была защищена try/catch
      с Sprint 1/3.1.1; новых проблем не найдено, поведение подтверждено
      по коду повторно.
- [x] Оверлей теперь либо надёжно появляется (если `SYSTEM_ALERT_WINDOW`
      выдан), либо тихо и безопасно пропускается с логом (если нет) —
      после переноса на главный поток `windowManager.addView()` больше не
      может провалиться из-за отсутствия `Looper`.

**Известные ограничения / не проверено в песочнице:** нет Android SDK,
устройства и Bluetooth-гарнитуры в этой среде — исправления проверены
чтением кода и трассировкой потоков выполнения, не запуском на устройстве.
Именно поэтому этот спринт помечен как «код готов», а не «завершён»: по
явному требованию пользователя Sprint 3.2 считается завершённым только
после успешного прохождения полного чек-листа на реальном устройстве.
